# Claude 控制台

一个基于 PyQt5 的桌面小工具，可以在窗口内直接和 Claude Code 对话，不需要打开终端。

当前工作区版本：**2.0**。原版 **1.0** 保留在提交
`69cd4b4feee27d8e4dfa94cf31f61f6021729fb6`；按发布指南创建并推送 `v1.0`
后，即可通过该标签检出或下载。当前版本整理不代表已发布到 GitHub；
两个版本的变更见 [CHANGELOG.md](CHANGELOG.md)，发布与核对步骤见
[docs/releasing.md](docs/releasing.md)。

| 版本 | 定位 | 主要内容 |
|---|---|---|
| 1.0 | 原版（单 AI） | 单模型对话、项目研读、开发、统一工作历史 |
| 2.0 | 当前版本 | 双 AI 协作（主 AI / 执行 AI、L0–L4 档次、交接协议 v3）、协作进度查询、运行中额度刷新与 25 秒超时恢复、80ms 流式批量渲染 |

- **界面内对话**：流式显示回复，工具调用以标签形式展示，对话记录实时可见
- **粘贴图片识别（新）**：在输入框直接 Ctrl+V 粘贴截图或拖入图片文件，
  控制台会用本地 OCR（RapidOCR / ONNX Runtime）把图片里的文字识别出来，
  随消息一起发给模型；输入框上方会显示缩略图、识别状态和识别字数，
  可随时移除。识别完全离线，不需要联网，也不依赖模型本身支持视觉输入。
  - 首次安装识别组件：
    `python3 -m pip install --user -i https://pypi.tuna.tsinghua.edu.cn/simple rapidocr-onnxruntime`
  - 其余依赖（numpy / opencv）本机已随 `python3-opencv` 安装
  - 若系统 OpenCV 与 numpy 2.x 不兼容（导入 cv2 报 `_ARRAY_API not found`），
    安装用户级兼容版：
    `python3 -m pip install --user --upgrade opencv-python-headless`
- **下载进度条（新）**：从 GitHub 安装技能时显示真实下载进度
  （MB / 百分比）、解压与安装步骤，并可随时取消；
  插件安装/卸载时显示进度窗口与已用时间
- **切换项目的对话定位（新）**：切换项目后，对话区停在该项目最近一轮
  用户提问的开头，不再跳回整段聊天的最上面；没有用户提问时定位到最后
  一条消息，空项目保持空态。快速连续切换或后台项目输出不会改变当前项目
  的定位；正常聊天仍会自动跟随到底部。
- **权限选择**：
  - `请求批准`：每次敏感操作（写文件、执行命令等）都弹窗询问
  - `帮我批准`：自动批准文件编辑，其他敏感操作仍会询问
  - `完全访问`：跳过所有权限确认（使用前会二次确认）
- **模型与思考强度（自动获取）**：
  - 模型列表在启动时向当前服务商自动拉取（读取 cc-switch 写入的
    `~/.claude/settings.json` 里的 `ANTHROPIC_BASE_URL` / token），
    并自动沿用 `[1M]` 等上下文后缀
  - 思考档位按服务商返回的 `supported_levels` 生成，下拉框直接显示英文原值
    （DeepSeek 当前为 `low / high / max`）；悬停可看到「服务商返回 N 档」及来源地址，
    状态栏也会显示本次拉取的来源与档位，便于确认不是内置兜底
  - 点击模型旁的 `↻` 可手动刷新；在 cc-switch 中切换服务商后，
    回到控制台窗口会自动重新拉取
  - 拉取失败时回退到内置的 DeepSeek Flash / Pro 列表
  - 对话中切换时会自动重建会话并保留上下文，选择会记住到下次启动
  - 模型选择放在输入框下方的折叠配置区：点底栏「模型配置」展开，
    再点一次收起（默认收起）。单模型模式显示「模型 / 思考」；
    勾选双 AI 协作后改为显示主 AI / 执行 AI 的模型与思考档位。
- **双 AI 协作（新）**：勾选底栏的「双 AI 协作」（位于「模型配置」按钮
  和额度显示左侧）后，折叠配置区里的单模型「模型 / 思考」换成主 AI /
  执行 AI 两个模型选择；取消勾选即恢复单模型行。两个下拉框都同时列出
  Claude 服务商模型和 Codex 登录模型，可任意组合；点「⇄」交换主从。
  - **展开 / 收起**：底栏顺序为「双 AI 协作」→「模型配置」→ 额度 →
    停止 → 发送。配置区只创建一次，展开和收起不会重置已选模型；
    切换模式或后台刷新目录也不会自动展开。
  - **同一行的角色与档次**：主 AI 模型、协作档次下拉框、「⇄」交换按钮、
    「复查」勾选框、执行 AI 模型和思考档位排在同一行；窄窗口可横向滚动。
  - **复查开关**：协作档次旁的「复查」默认勾选，按档次执行原有的主 AI
    验收策略。取消后本轮不产生独立的主 AI 复查 / 验收调用，适合简单、
    已验证的改动；执行者自检、失败接管和任务结果判定不受影响，失败或
    漏项仍会明确显示为未完成。开关状态会保存，重启、切档次、折叠配置
    都不会重置。
  - **独立思考档位**：主 AI 与执行 AI 各有独立的「思考」下拉框，按各自
    模型支持的档位生成和保存；交换主从时两个档位一起交换。
  - **按档次分工，不再按比例凑点**：一次运行被拆成读取、定位、检索、
    上下文压缩、思考决策、方案设计、执行修改、运行监控、输出汇报等工作
    部件；难度高的交给主 AI，难度低的交给执行 AI。五个档次从难到易：
    `L0 全主档`（全部主 AI 做）、`L1 主控重档`（主 AI 做思考、设计和主要
    执行，从 AI 只读取/定位/检索/监控）、`L2 中高档·主从配合`（默认：从
    AI 先压缩上下文，主 AI 给简洁指令，从 AI 执行监控，可中途询问，主 AI
    验收）、`L3 低档·从主导`（主 AI 只下发契约，从 AI 自主执行；全部通过
    时跳过主 AI 验收）、`L4 全从档`（全部从 AI 做）。端点档次另一个模型
    完全不参与。
  - **主 AI 负责**：理解需求、拆任务/下发契约、思考设计、处理疑难、最终
    验收和接管；**执行 AI 负责**：读取、定位、检索、上下文压缩、执行修改、
    运行监控和常规汇报。
  - **流程**：较长的历史先由执行 AI 压缩 → 主 AI 规划或下发契约 → 按任务
    顺序执行（同一时间只有一个写入者）→ 执行 AI 可用一行 `DUAL_ASK` 请求
    二次指导 → 失败时主 AI 接管 → 按档次决定是否验收 → 汇总档次、调用
    次数、跨模型提示字符数、上下文压缩量、费用和 tokens。
  - **省额度机制**：跨模型只传压缩后的任务指令、询问和指导，不传隐藏
    推理或整段聊天；短上下文不额外压缩；低档全部通过时省掉验收调用；
    取消「复查」可跳过独立验收；高难工作才调用主 AI，简单工作不进主 AI
    上下文。
  - **余额 / 额度**：位于底栏「模型配置」按钮右侧、停止按钮左侧。协作模式下同时显示
    主 / 从两个模型的额度；单模型模式下显示当前所选模型的余额。Claude 侧
    读取 DeepSeek 余额接口；Codex 侧读取 ChatGPT 登录的 5 小时窗口 / 每周
    窗口用量。点「↻」可手动刷新，也会每 5 分钟自动刷新；任务运行中同样可以
    刷新，查询在后台线程进行、不会阻塞界面。同一模型的自动刷新会去重，
    超过 25 秒未返回会显示「查询超时 · 点 ↻ 重试」，不会一直停在“查询中…”；
    切换模式或模型后，旧的异步查询结果不会覆盖当前额度，查询失败会以红字
    显示明确状态。
  - 双 AI 协作走命令行无交互模式：`请求批准` 会按“自动批准文件编辑”执行，
    `完全访问` 才会跳过全部限制；界面会给出提示。
  - 交互、消息、工具标签和余额都保留在 Claude 控制台内，不跳转外部窗口。
  - **完成判定**：CLI 正常返回与任务验收分开判断。任务、接管、端点执行和
    最终验收必须返回 `DUAL_RESULT` 结构化状态及非空验证说明；缺失报告或
    `blocked / failed` 不会显示为通过。模型报告仍需结合实际工具输出检查。
  - **工作点统计**：工作点只用于粗略展示主 AI / 执行 AI 的预计工作量，
    不参与角色分配。角色只由工作部件难度决定。
  - **交接协议 v3**：共享状态卡保留任务 ID、工作部件、用户约束、接口决定、
    修改文件、验证证据和未解决项。原始输入和完整报告单独保存，不再截断
    JSON 或反复注入聊天全文；较长内容通过完整文件引用读取。模型间可用
    英文/伪代码的压缩指令、`DUAL_ASK` 压缩询问和 `DUAL_GUIDE` 短指导互通。
    有效摘要单独落盘，主 AI 按需核实原文；约束不按字符或条数截断。
  - **合并与续接**：连续同角色任务合并一次调用，顺序和逐项验收不变；角色
    各自恢复 Claude/Codex 会话。规划、执行、验收每轮重申权限及阶段，主从
    即使使用同一模型也不会共用会话。会话明确失效且没有输出或工具操作时，
    仅重建一次；普通错误不会自动重放写操作。恢复会话仍可能计费历史输入。
  - **交接与停止**：失败后从现场接管；成功前缀不重复实施，未完成项不静默
    跳过。最终验收修复未完成任务时必须给出对应 ID 和逐项验证证据，通用的
    `passed` 结论不能覆盖漏项。取消后不会继续升级或验收；新建对话需等待
    线程停止。同一对话的下一轮自动携带上轮状态快照，换模型后仍保留交接；
    新建对话会清除该关联。
  - **本地记录**：每轮记录保存到 `${XDG_STATE_HOME:-~/.local/state}/claude-console/dual-runs/`，
    完成消息显示具体目录。包含完整输入、计划、原始报告、共享状态和最终
    结果；写入采用原子替换。详见 [协作协议](docs/dual-ai-protocol.md)。
  - **回归验证**：`QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s tests -v`。
    测试使用模拟 CLI 和临时项目，不调用真实模型或消耗账户额度。

- **统一工作历史**：同时读取 `~/.claude/projects` 与 `~/.codex/sessions`，
  可按「当前项目 / 全部项目」和「全部来源 / Claude / Codex」筛选
  - Claude 会话双击后可在界面内恢复继续
  - Codex 会话双击后预览内容，并可转到终端执行 `codex resume`
- **引用回复（新）**：每条消息右上角有「↩ 引用」，点击后输入框上方会出现
  引用条；发送时会把你引用的原文一起带给模型，并在你的消息里显示引用摘要。
- **对话内直接显示图片（新）**：当回复里包含本地图片路径或 Markdown 图片
  （如 `~/桌面/图片.png`、`![](/path/a.jpg)`）时，控制台会直接在对话气泡里
  显示图片缩略图，点击即可打开原图，不再需要去文件夹里找。
- **主对话问答（新）**：在任意对话气泡里选中一段文字，右键选择
  「针对选中内容提问」，或点输入框下方的「选中提问」按钮，会打开
  悬浮问答窗（Ctrl+Shift+W 可随时召回）。也可以直接点「问答窗口」按钮，
  **不必先选中内容**，直接输入问题即可；若已选中文字，问题会自动带上引用。
  回答可一键「插入对话」，交互与研读页的解释栏问答一致。
  - 问答窗口的输入框同样支持 **Ctrl+V 粘贴截图 / 拖入图片**，可一次附带最多
    8 张；本地 OCR 识别完成后随问题一起发送，附件条上会显示识别字数并可移除。
- **进度查询（新）**：点「选中提问」右侧的「进度查询」按钮，会在按钮
  上方弹出小窗，显示当前任务属于主对话还是问答窗口、权限是否正常/是否正在等待
  授权、最近一次输出或工具调用距今多久、本轮工具次数，以及预计剩余时间。
  双 AI 协作运行时会同时显示协作档次、当前角色和任务 ID；切到别的项目后，
  后台项目仍在运行时也会报告它。浮窗每秒自动刷新，并会额外显示 Claude 启动的**后台任务**：编译、打包、
  下载/安装、解压等进程的已运行时间、CPU、真实百分比（ninja `[N/M]`、
  wget/curl、git、apt/dpkg、CPack 等日志格式）、当前日志行、预计剩余时间，
  以及本机实时网速（↓/↑）。后台任务结束后会弹桌面通知并在状态栏提示，
  不再需要反复询问“好了吗”。
- **生图 / 生视频（新）**：
  - 对话页顶部「生成 ▾」可直接生成图片或视频；也可以直接在输入框输入
    `/img 描述`、`生成图片：描述`、`/video 描述`、`生成视频：描述`。
  - 生成结果会以缩略图卡片显示在对话里，文件保存到
    `<项目>/.claude-console/generated/`。
  - 研读页的「生成配图 / 生成视频」会按当前研读主题或选中内容生成，
    结果显示在解释栏下方，并随研读记录一起保存。
  - 图片由共享技能 `media-tools` 调用 Agnes / SenseNova / SiliconFlow；
    视频可选 SiliconFlow（`siliconflow_video.py`，模型 MiniMax-H3）或 Agnes。
    需要在 `~/.dsh/secrets/media-tools.env` 配置服务商 Key
    （`AGNES_API_KEY` / `SENSENOVA_API_KEY` / `SILICONFLOW_API_KEY`）。
  - **一把 Key 同时生图和生视频**：推荐 SiliconFlow。图片用
    `Kwai-Kolors/Kolors`（官方定价免费），视频用 SiliconFlow 的
    `/v1/video/submit` + `/v1/video/status`（按次计费）。
  - 已部署的媒体相关技能：`media-tools`、`vision-review`、`atlas-cloud`、
    `seedance-2-5-skill`、`universal-video-prompt-skill`、
    `handdrawn-tech-illustrations`、`gpt-image-2-style-library`、
    `web-artifact-designer`。
- **技能与插件管理**：
  - 技能库：从 GitHub / 本地文件夹安装、删除、打开目录、同步到两端
  - **分类管理（新）**：技能按「生图 / 视频」「PPT」「开发 / 代码」「设计 / 网页」
    「其他」分组显示，顶部可按分类筛选；右键技能可手动修改分类。
  - 插件：Claude 与 Codex 并排管理，支持安装、启用/禁用、卸载
- **代码研读页（新）**：
  - 在「对话」页勾选 **研读模式** 后，主对话框的提问会自动切到「代码研读」页，
    并把 Claude 的回答写入左侧解释栏；回答里的代码位置会变成链接。
  - 左侧是 AI 解释栏，右侧是带行号的源码栏。点击解释里的 📄 链接，
    右侧会自动切换文件、滚动到目标块的起始行，并用高透明度淡蓝色标出目标行。
  - **VS Code 风格的多页源码**：打开过的文件会保留为页签，可自由切换、
    拖动排序或点 × 关闭；支持「← / →」在访问过的代码位置之间前进后退。
  - **代码目录树**：右侧可显示项目目录（自动隐藏 build、.git、node_modules 等），
    双击文件即可打开；可用「目录」按钮显示/隐藏。
  - **语法高亮**：使用本机 VS Code 的 Cute Pink Light Theme 配色
    （注释绿、关键字蓝、字符串暗红、类型蓝绿、函数棕、数字绿）。
  - **独立窗口（按项目各自独立）**：研读页默认是主窗口页签，也可以点「独立窗口」
    或对话页的「独立窗口」开关，把它放到单独窗口和主对话框并排使用。
    每个项目都有自己的研读页和独立窗口：主窗口在项目之间来回切换时，
    已弹出的窗口不会被切走或覆盖，多个项目的窗口可以同时开着、互不影响；
    窗口标题会显示所属项目名，关闭窗口会自动收回该项目自己的页签。
  - 解释栏支持两种对话方式：
    1. 主对话框继续总体学习（研读模式）；
    2. 在解释栏选中一段文字 → 点「针对选中内容提问」→ 在下方独立的问答框中追问，
       回答只进入问答区，不会覆盖解释原文。
  - **研读记录（新）**：顶部「保存研读 / 载入研读 / 返回刚才」把解释栏、局部问答
    和生成的配图/视频保存成记录，之后可随时载入或回到上一份研读。
    载入记录后继续研读、追问、补充解释或增删配图，改动会自动同步回该记录文件，
    下次载入时看到的即是修改后的内容。
  - **按项目独立记忆**：每个项目的「研读模式」开关、当前主页签（对话 / 代码研读 /
    会话历史…）、解释栏内容、局部问答和配图各自独立。切到别的项目不会把研读模式
    或页签带过去；切回原项目时会自动恢复它自己的模式和内容，不会被清空。
  - **精确跳转**：研读请求会自动附带项目的「符号索引」（真实文件 + 真实行号）。
    链接格式支持 `[[code:相对路径:起行-止行|函数或类名]]`，其中符号名用于校验：
    模型行号估算偏了时，会自动定位到该函数/类的真实定义块；同名文件分布在多个
    模块时，也会优先选择真正包含该符号的文件。
  - 每次局部问答的**最底部**会直接显示「添加到解释栏 / 删除」按钮，
    不再弹窗询问。
  - 顶部可载入任意 Markdown 讲解文件；不再内置某个特定工程的示例。
    代码跳转按当前项目的相对路径解析，适用于其他算法/工程代码。
- **代码开发页（新）**：
  - **多文件夹授权**：可一次多选允许修改的代码文件夹，之后还能继续添加。
    顶部所有按键（修改模式、添加/移除、刷新、标记节点、检查新代码、
    清空、保存开发/载入开发、独立窗口）收在同一行，不再单独占一行显示文件夹；
    点「− 移除」会打开已添加列表，多选后一次移除（不会删除磁盘文件）。
    文件夹之外的任何修改都必须逐次申请，与命令询问模式无关。
  - **每个项目各自独立**：和代码研读一样，每个项目有自己的代码开发页、
    自己的对话和待确认改动；切换项目不会串台。
  - **多文件页签**：双击左侧目录可以同时打开多个代码文件，右侧以页签形式
    保留，可拖动排序、切换或点 × 关闭，与代码研读的代码区一致；每个页签
    各自维护改动标记、撤回/前进和自动保存。
  - **目录文件操作**：左侧代码目录支持右键菜单，可新建文件、新建文件夹、
    重命名、删除和刷新（类似 VS Code）；删除前会二次确认，删除目录会连同
    其中的文件一起移除。
  - **独立窗口**：点顶部「独立窗口」可把当前项目的开发页放进单独窗口，
    和主对话框并排使用；不同项目可以同时各开一个开发窗口。关闭窗口或
    再点「收回页签」即可放回主窗口。切换项目时页签顺序会保持
    「对话 / 代码研读 / 代码开发」，不会与研读页互相挤乱布局。
  - **不再弹出权限确认窗**：开发模式下读写、Bash 等操作一律放行，不会出现
    单独的权限确认弹窗。是否覆盖代码只由顶部「修改模式」决定：
    - **自动覆盖（不确认）**：AI 改完直接写入原文件，不显示对比、不等确认；
    - **每轮确认一次**：每轮 AI 修改结束后，一次性确认覆盖本轮全部改动；
    - **每次都确认**：每个文件都要在改前/改后预览里逐个确认后才覆盖。
  - **页内改前 / 改后预览**：AI 改完不再弹出新窗口，而是在开发页右侧直接显示
    两栏代码，并暂时收起代码目录栏留出对比空间；左侧对话仍可继续提要求。
    改动行用高透明度颜色标出，行号和所属文件夹都带红色 ❗。
  - **可编辑后再确认**：右侧「修改后」一栏可以直接改写 AI 的代码，点
    「确认覆盖原代码」才真正写入；「取消并还原」恢复 AI 修改前的内容。
    也可以点「继续对话修改这段」，对同一段代码反复提要求，满意后再确认。
    点「返回代码」可随时收起对比、恢复代码目录。
  - **保存开发 / 载入开发**：顶部「保存开发 / 载入开发」在独立窗口按钮旁，
    可把开发对话、允许修改的文件夹和待确认改动保存成记录，之后再载入继续。
    载入记录后继续对话、增删文件夹或确认/取消改动，都会自动同步回该记录文件，
    下次载入时就是修改后的版本。新建对话或移除当前项目时，开发会话会像
    代码研读一样自动收起并清空。
  - **自动保存与撤回 / 前进**：在右侧编辑器里修改代码后会自动保存到磁盘
    （停止输入约 0.7 秒）；「保存 / 重新加载」旁新增 ↶ / ↷ 两个符号，
    可撤回或前进代码修改，文件也会跟着自动保存。点「确认覆盖原代码」后，
    ↶ 也能撤回这次覆盖（↷ 可再前进回来）。
  - **手动标记节点**：点顶部「标记节点」把当前所有文件记录为「新代码起点」，
    之后再改动的行会用红色 ❗ 标出。系统不再在「检查新代码」或 AI 修改后
    自动挪动起点；需要新的起点时手动再点一次。
  - **检查我的新代码**：一键把「标记节点」之后自己写的新代码发给 AI 做只读
    检查（逻辑、边界、异常、可维护性等），不会改动文件，也不会自动挪动起点。
  - **重新打开程序时文件夹为空**：允许修改的文件夹不再跨进程恢复，
    需要时重新添加；主动「载入开发」仍会带回记录里的文件夹。
  - 左侧 AI 对话栏的默认宽度调整为原来的 3/4，把更多空间留给代码。
  - **对话栏 + 独立问答窗**：左侧是 AI 对话栏；「问答窗口」/ Ctrl+Shift+E
    可打开悬浮问答窗，它使用独立的消息记录和后台会话，内容与主对话互不同步。
    「针对选中提问」不再弹出独立窗口，而是把源码或对话里选中的内容直接带入
    下方对话输入框，输入问题后发送即可。
- **项目列表**：常用目录一键切换，支持打开文件夹 / 终端 / VS Code
- **运行命令**：常用 shell 命令在外部终端执行，支持历史补全和收藏
- 白粉配色，F5 刷新会话列表

## 与 Codex 共享

- **技能库**：实体存放在 `~/.agents/skills`，并软链接到
  `~/.claude/skills` 与 `~/.codex/skills`，安装一次两边都能用。
- **工作历史**：`~/.agents/history` 下提供 `claude-projects` 与
  `codex-sessions` 两个只读入口；控制台的「会话历史」把两边合并展示。
- **插件**：Claude 插件使用 `.claude-plugin`，Codex 使用 `.codex-plugin`，
  格式不兼容，因此不做目录互链，只在控制台中统一管理。
- 已在 `~/.claude/CLAUDE.md` 与 `~/.codex/AGENTS.md` 写入共享入口说明，
  两边的 AI 新会话都知道去哪里查找对方的历史。
- 详细说明见 `~/.agents/README.md`。

## 运行

### Windows

双击 `run.bat`，或在项目目录执行：

```bat
.venv\Scripts\python.exe main.py
```

- 已建好 `.venv` 时 `run.bat` 会自动使用它；也可以加 `--background`
  参数用 `pythonw` 启动（不弹控制台窗口）。
- 开始对话时会优先使用 `claude.exe`（原生安装或 `claude-agent-sdk`
  自带的版本）；没有 `claude.exe` 时，CLI 相关功能通过 `cmd.exe` 调用 npm
  安装的 `claude.cmd`。
- 技能库链接优先用符号链接，没有开发者模式时自动退回目录联接（junction）。
- 后台任务/网速监控依赖 Linux 的 `/proc`，Windows 下显示为「无 / —」。

### Linux

```bash
./run.sh
```

或安装到应用菜单（已创建）：

```bash
cp claude-console.desktop ~/.local/share/applications/
```

## 依赖

安装 Python 依赖：

```bash
python3 -m pip install -r requirements.txt
```

- `PyQt5`
- `claude-agent-sdk`：程序会优先加载 `vendor/` 目录里的版本；没有 `vendor/`
  时使用 pip 安装的版本
- 图片文字识别：`rapidocr-onnxruntime`（模型随包离线携带）
- `numpy` / `opencv-python`
- Claude Code CLI（Linux 上程序会自动在 `~/.nvm/versions/node/*/bin`
  等常见位置查找，即使从桌面启动时 PATH 不完整也能工作；Windows 上会查找
  `%APPDATA%\npm` 等目录，并优先使用 `claude.exe`）

## 说明

- 对话使用 `claude` CLI 的非交互流式接口，登录状态沿用你现有的 Claude Code
  配置；模型与思考强度可在对话页底栏点「模型配置」展开后切换。
  双 AI 协作的「复查」开关也在同一折叠配置区，取消后可跳过独立验收。
- 会话 ID、历史记录与终端里运行的 Claude Code 完全一致，可以互相恢复。
- 若升级 `claude-agent-sdk`，请重新安装到 `vendor/` 目录。
