## 修复行为

1. 同一界面的同一对话在内存中保留角色会话句柄。项目、角色、模型、有效思考档位、
   权限、CLI 路径和服务商/账户指纹不兼容时重新建会话。新对话、恢复其他历史会话、
   取消或调度异常清除相关句柄。磁盘快照本身不会自动恢复会话。
   指纹不包含明文凭据；Codex 认证文件变化也会保守地使续接失效。
2. 新一轮仍完整保存历史；已有兼容角色只收到新请求和中间新增消息。
   未新增历史时不重复调用压缩模型；失效重建仍读取完整输入。
   规划只读和执行权限继续通过每次 CLI 参数分别配置，不提高权限以续接。
3. 小状态索引包含约束和逐项证据，信息足够时不强制再读取相同状态文件；
   大索引和冲突仍要求定位完整记录。不为凑双模型调用创建重复调查或汇报。
4. 可从有效子项恢复缺失的顶层验证；其他可补齐的 passed 报告只读补报一次。
   Claude 补报禁用工具；其他补报使用只读权限，禁止重跑实施和测试。
   明确失败、传输失败、取消、未知/重复/乱序 ID 不进入补报捷径。
5. DUAL_ASK 的 `completed` 可包含已验证的连续成功前缀。
   调度器保存这些证据，指导后只发送剩余任务；不接受无证据或非连续前缀。
6. 用户保留的令牌命令放入 `pending_user_actions`。本地材料准备可以完成，
   实际发布仍必须明确为未执行；真正阻塞当前目标的工作仍是 blocked。

## 用量口径

Claude 的 `input_tokens` 不包含缓存读写：总输入为三者之和。
Codex 的 `input_tokens` 已包含缓存，不重复加 `cached_input_tokens`。
命中比例使用有完整分子、分母的调用加权计算，并显示数据覆盖次数；
缺失值不伪装为 0，未返回金额显示未知。缓存命中也不等于免费。
正常 SDK 保存仅含用量等元数据的 0600 文件至 `single-calls/`，不保存提示正文或工具参数。
CLI 调用日志新增逐次耗时、退出码、工具数、费用和标准化指标，旧日志可继续读取。
